Integration Overview

Three new features enhance the MapScreen component with payment processing, flexible itinerary management, and intelligent arrival detection.

Architecture

MapScreen Component - Main orchestrator
useMapState (existing) - Core state management
usePaymentState (new) - Payment handling
useItineraryEditor (new) - Stop insertion
useArrivalDetection (new) - Geofencing

Key Dependencies

  • Firebase for trip plan persistence
  • Browser Geolocation API for location tracking
  • Payment provider API (Stripe/PayMongo/GCash)
  • OpenStreetMap for routing display
Note: Test trips skip payment processing. Non-test trips require payment completion before navigation can begin.

Data Flow Architecture

State Dependencies

selectedPlan → determines payment amount
isNavigating → triggers arrival tracking
currentNavStopIndex → current stop for geofencing
routeStops → available stops for insertion
completedStops → tracks progress for validation

Error Recovery Flows

  • Payment failure → User selects different method & retries
  • Network error → Exponential backoff retry (max 3x)
  • Concurrent edit → Version check rejects, ask to reload
  • Low GPS accuracy → Show warning, allow manual override
  • Geolocation denied → Fallback to manual marking

Implementation Notes

1. Payment Provider Choice

Decide between Stripe, PayMongo, or GCash integration. Update usePaymentState accordingly.

2. Geofence Configuration

Default 100m is conservative. Test in Philippines region for GPS accuracy before adjusting.

3. Concurrent Edit Prevention

Consider adding version stamps to itineraries to prevent conflicts when multiple people edit.

4. Battery Impact

Arrival detection uses enableHighAccuracy: true. Consider user warning about battery drain.

5. Offline Support

Payment status should persist in localStorage until network returns.

6. Accessibility

Ensure arrival notification is announce-able for screen readers.

7. Mobile Testing

Test on actual devices with real GPS, not just browser dev tools.
